## 📌 Overview

PermScan is a machine learning-based Android malware detection system that analyzes app permission requests to identify potentially malicious applications. By leveraging binary permission features extracted from 29,332 Android apps, the system achieves **95.24% recall** and **0.9815 AUC-ROC** using optimized Logistic Regression models.

### Why This Matters
Android malware continues to evolve, with malicious apps increasingly using permission combinations to bypass traditional detection methods. PermScan identifies suspicious permission patterns that correlate with malware, providing:
- **Early detection** before installation
- **Privacy protection** by identifying data-hungry apps
- **User empowerment** through an accessible GUI
- **Research insights** into malware permission patterns

## 📊 Analysis Phases

### Phase 0: Environment Setup & Data Loading
- Configured reproducible environment with `random_state=42`
- Loaded dataset (29,332 apps × 87 columns)
- Identified typo columns and manufacturer-specific variants
- Discovered 21,841 duplicate rows (74.46%)

### Phase 1: Exploratory Data Analysis (EDA)
- **Univariate**: Permission request rate distribution
  - Mean request rate: 10.99%
  - 1 permission >95% (INTERNET)
  - 57 permissions <5% (very rare)
- **Bivariate**: Permission-target correlations
  - 81/86 permissions statistically significant (p < 0.05)
  - 102 highly correlated permission pairs

### Phase 2: Data Cleaning
- Removed 21,841 duplicate rows
- Fixed typo: `android.permission.android.permission.READ_PHONE_STATE`
- Consolidated redundant badge/launcher permissions
- Final shape: 7,491 rows × 85 columns

### Phase 3: Feature Engineering
Created aggregate features:
- `total_permissions` - Permission count
- `rare_permissions_count` - Count of rare permissions (<5%)
- `high_risk_score` - Risk-weighted permission score

### Phase 4: Feature Selection & Train-Test Split
- Removed redundant manufacturer-specific badge permissions
- Stratified split preserving 65/35 class distribution
- Created scaled and unscaled versions

### Phase 5: Supervised Learning
| Model | Recall | F1-Score | AUC-ROC |
|-------|--------|----------|---------|
| Logistic Regression | **0.9524** | **0.8969** | **0.9815** |
| Random Forest | - | - | - |

### Phase 6: Unsupervised Learning (Clustering)
- KMeans: k=5 clusters, best silhouette score
- DBSCAN: Density-based clustering with noise detection

### Phase 7: Model Comparison & Selection
- **Best Overall Model**: Logistic Regression
- **Best Clustering Model**: KMeans (k=5)

### Phase 8: Model Explainability (SHAP) - Planned
- Global feature importance
- Individual prediction explanations
- Benign vs. malicious comparison

### Phase 9: Risk Predictor & GUI - Implemented
- Tkinter-based interactive application
- User selects permissions from scrollable list
- Real-time malware probability prediction

### Phase 10: Visualizations & Reporting - Planned
- Consolidated figures and summary tables
- Exportable report artifacts

### Running the GUI

```bash
# Install dependencies
pip install -r requirements.txt

# Train and save the model (first time only)
python -c "
import joblib
import pandas as pd
from sklearn.linear_model import LogisticRegression

# Load training data
X_train = pd.read_csv('data/splits/X_train_scaled.csv')
y_train = pd.read_csv('data/splits/y_train.csv').values.ravel()

# Train model
model = LogisticRegression(random_state=42, class_weight='balanced')
model.fit(X_train, y_train)

# Save model and features
joblib.dump(model, 'models/best_model.pkl')
joblib.dump(X_train.columns.tolist(), 'models/feature_columns.pkl')
"

# Launch GUI
python gui.py
```

## 📈 Results Summary

### Model Performance
- **Logistic Regression**: 95.24% recall, 0.9815 AUC-ROC
- **Key insight**: Rare permissions with high conditional probability are strongest signals
- **P(malware | READ_PHONE_STATE)** = 97.2% (11.5x baseline)

### Data Quality Insights
- 21,841 duplicates removed (74.46% of raw data)
- Class balance shifted from 50/50 to 65/35 after deduplication
- 57 permissions requested by <5% of apps (candidates for removal)
